1) מאיפה הכל התחיל
------------------
הפרויקט נולד מצורך מעשי במלון The Yacht: להחליף טפסי נייר מצולמים בבדיקות
חדרים (רשימת ריג'קטים מאושרת) באפליקציית ווב דיגיטלית בעברית (RTL), נוחה
לשימוש בטלפון ובמחשב.

קוד הפרויקט: WEB-HKR-The-Yacht-MP-Room-Inspection-Form
שם תצוגה: בדיקת חדרים — The Yacht
טופס: טופס בדיקת חדר

האתר עלה ל־GitHub תחת החשבון Michael2001papis, ונפרס לפרודקשן ב־Vercel:
https://web-hkr-the-yacht-mp-room-inspectio.vercel.app
ריפו:
https://github.com/Michael2001papis/WEB-HKR-The-Yacht-MP-Room-Inspection-Form

בהתחלה נבנתה אפליקציה סטטית (HTML + JavaScript + CSS) בלי React/npm/build.
נוספו בהדרגה: checklist מלא, שמירה מקומית, PDF, כפתורי "הכל תקין", גיבוי מלא,
ואחר כך ניסיון לסנכרון ענן דרך Supabase Free (Auth + טבלת inspections + RLS).
חלק מהעבודה נעשתה גם דרך Cursor Agent (נשארו PRs סגורים בהיסטוריה).

בשלב מאוחר יותר בוטל השימוש הפעיל ב־Supabase בממשק (כי ההגדרה לא מולאה /
לא הייתה נוחה לשימוש היומיומי), וההתחברות הוחלפה לשער מקומי פשוט למשתמש
יחיד. במקביל שופרו עיצוב וחוויית שימוש למובייל ולמחשב, נוסף timeout של
90 דקות ללא שימוש, ותוקן באג שבו מסך ההתחברות נשאר מוצג מעל מסך הבית.


2) מה התפקיד של האתר (ייעוד)
-----------------------------
האתר הוא כלי עבודה פנימי לבודק/צוות במלון, שתפקידו:

• לפתוח בדיקת חדר חדשה (בדיקה 1 או בדיקה 2 / בדיקה חוזרת)
• לעבור על רשימת סעיפים מאושרת ולסמן: תקין / לא תקין
• להוסיף הערות לפריט ולכתוב הערות כלליות לכל הבדיקה
• לשמור אוטומטית כל שינוי במכשיר (בלי לאבד עבודה)
• להמשיך בדיקה שטרם הסתיימה
• לחפש חדר, לראות חדרים שמורים, למחוק חדר במידת הצורך
• ליצור PDF מסודר לבדיקה בודדת או גיבוי מלא לכל החדרים
• להגביל כניסה למשתמש מורשה בלבד (כרגע משתמש יחיד)

המטרה העסקית: לחסוך זמן, לצמצם נייר, לשמור תיעוד דיגיטלי ברור של ליקויים
ותקינות בחדרים.


3) מה מייחד אותו (ייחוד)
------------------------
• מבוסס על רשימת ריג'קטים מאושרת — ניסוח וסדר מדויקים, לא להמציא סעיפים
• עברית מלאה ו־RTL מהיסוד (לא תרגום מאוחר)
• מותאם לעבודה בשטח בטלפון (כולל Galaxy) וגם במחשב/טאבלט
• Offline-first בפועל: הנתונים חיים במכשיר גם בלי רשת
• PDF נוצר בדפדפן (html2pdf) בלי שרת ייעודי
• מיתוג The Yacht: צבעי ירוק־ים / זהב, לוגו ורקעי צילום (PCOG/CCOG)
• אין צורך בהתקנת אפליקציה מחנות — נפתח בדפדפן / כ־PWA-ish
• משתמש יחיד פשוט: MP2001 / סיסמה מקומית, בלי הרשמות מורכבות
• התנתקות אוטומטית אחרי 90 דקות ללא שימוש (הנתונים נשארים במכשיר)


4) מבנה טכני מלא
----------------
סוג: SPA סטטי (Single Page Application)
טכנולוגיות: HTML5, JavaScript (Vanilla), CSS מותאם, Google Font Heebo
Hosting: Vercel
בקרת גרסאות: Git + GitHub (ענף main)
אין: package.json, React/Vue, TypeScript, CI/tests כרגע

קבצים עיקריים:
• index.html — כל המסכים במקום אחד
• static/css/styles.css — עיצוב, אנימציות, רספונסיביות
• static/js/app.js — ניווט בין מסכים ולוגיקת UI
• static/js/auth.js — התחברות מקומית + idle timeout
• static/js/storage.js — localStorage לפי משתמש
• static/js/checklist-data.js — CHECKLIST + APP_META
• static/js/pdf.js — יצירת PDF / גיבוי מלא
• static/js/sync.js — שכבת סנכרון לענן (קיימת בקוד, לא פעילה)
• static/js/supabase-config.js / supabase-client.js — ריקים / מכובים
• supabase/schema.sql — סכמת DB ישנה ל־Supabase (לא בשימוש פעיל)
• README.md / SUPABASE_SETUP.md — תיעוד

נכסים גרפיים:
• static/IMG/LOGO.png
• static/IMG/PCOG.jpg (רקע מובייל)
• static/IMG/CCOG.jpg (רקע דסקטופ)
• static/assets/logo.svg ו־Heebo.ttf — קיימים אך לא בשימוש פעיל ב־HTML/CSS

6) התחברות (מצב נוכחי)
----------------------
שם משתמש: MP2001
סיסמה: 1234
סוג: בדיקה מקומית בדפדפן בלבד (לא ענן)
Session: localStorage (yacht-local-session-v1)
Timeout: 90 דקות ללא פעילות → התנתקות אוטומטית
אין יצירת חשבון בממשק
אין Supabase Auth פעיל

הערה חשובה: זו אינה אבטחה ברמת שרת — הפרטים נמצאים בקוד הלקוח.
מתאים למשתמש יחיד / שימוש פנימי, לא להגנה מפני תוקף מתוחכם.


7) שמירת נתונים
---------------
הכל נשמר ב־localStorage במכשיר תחת מפתח לפי משתמש (local-mp2001).
שמירה אוטומטית תוך כדי מילוי הטופס.
אין כרגע סנכרון אוטומטי בין טלפון למחשב — כל מכשיר שומר לעצמו.
ניתן לייצא PDF כגיבוי/שיתוף ידני.
שכבת Supabase/Mongo/ענן אחר — לא פעילה כרגע (Mongo trial נגמר אצל המשתמש;
Supabase בוטל בממשק).


8) תוכן הבדיקה (Domain)
-----------------------
שדות מטה: מספר חדר, סוג חדר, מזהה נוסף, תאריך, מספר בדיקה (1/2).
לכל פריט: exists (לאופציונליים), status (ok / not_ok), note.
הערות כלליות ברמת הבדיקה.
ליקוי בלי הערה — חוסם מעבר לסיכום.

קטגוריות עיקריות (10):
נגרות | גבס/צבע | ריצוף וחיפוי | אלומיניום וזכוכית | אינסטלציה |
ספרינקלרים | מיזוג אויר | חשמל ובקרה | אביזרי אמבטיה | אבזור חדר

כלי עזר בטופס:
• סימון הכל תקין בקטגוריה
• סימון כל החדר תקין
• ביטול בחירה בלחיצה חוזרת על אותו סטטוס


9) עיצוב וחוויית משתמש
